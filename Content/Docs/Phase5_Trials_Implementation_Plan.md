# Phase 5 — Trials System (UE 5.8)

**Started:** 2026-10-22  
**Source:** [Architecture Design Plan](./Architecture_Design_Plan.md), Phase 5 (Weeks 10–11)

## Outcome

A player can start a qualifying trial, see objective progress, complete or fail it, and receive the configured reward exactly once per completion. Combat, skill, and exploration trials use the same native component and data definition; Blueprints may hold asset data and visuals but not trial rules.

## Implementation order

1. **Native core:** `UTrialDataAsset` defines trial identity, type, objectives, prerequisites, repeatability, and rewards. `UTrialComponent` tracks one active attempt, validates starts, accepts objective events, computes progress, and emits state events. Attach it to the player. Add automation tests for invalid definitions, requirements, progress, failure, completion, repeatability, and reward delivery.
2. **Gameplay event hooks:** Wire enemy kills, skill use, and location entry to specific objective IDs. Do not award progress merely for spawning or entering PIE; each event must identify its actor/skill/location and prevent unintended duplicate credit. Add focused tests for each hook.
3. **Rewards:** Start with XP into `ExperienceComponent`, then add inventory items, skills/traits, and attribute changes as separate validated reward types. Reward application must be idempotent and avoid partial payouts. Define failure penalties only after the desired loss rules are agreed.
4. **Sample content:** Create one Combat, one Skill, and one Exploration trial asset in `/Game/Data/Trials`, plus minimal world activation/completion points for a playable loop. Add Crafting after the first three types work.
5. **UI and acceptance:** Native-bound trial list/detail/progress widget, objective feedback, completion/failure notice, and reward preview. Verify the full player flow in PIE, including a failed attempt and one-time/repeatable behavior. Save the map/assets and document manual checks.

## Hands-on PIE checks

Current `/Game/Input/IM_ActionRPG` mapping: **F** activates `IA_Interact` for manual pickups; **E** activates quick-use slot 10. Older phase notes that call E the interact key are out of date. Trial start/goal markers activate by overlap, not by pressing F.

1. Open `/Game/NewMap` and Play. Enter the First Steps start marker `(0,150,40)`, then the goal marker `(0,550,40)`; check the tracker completes and grants 100 XP. Re-entering the one-time start should not grant a second payout.
2. Enter Dash Practice at `(550,100,40)`; collect/use the nearby Dash skill (`SKILL_DASH`). Check one Dash use completes the trial for 100 XP. Enter the marker again and repeat to confirm a second completion and payout. Use **Abandon Trial** on another attempt to confirm failure count increments without a reward.
3. Enter Training Combat at `(500,-300,40)`, use the nearby Melee Attack pickup, and defeat the labeled Training Enemy at `(750,-300,90)`. Check exactly one completion and 150 XP. An unattributed/environmental death should not count.
4. Assign 100 earned XP to Blacksmith in the class panel to unlock its crafting skill. Then enter Forge an Iron Sword at `(240,300,40)`. Collect the nearby 2 Iron Ore, assign/use Blacksmith Crafting, and confirm the recipe consumes 2 ore, creates 1 Iron Sword, and completes the trial for 200 XP. Crafting without the ingredients must not progress it. The Phase 4 Blacksmith setup details remain in [Days 49–52 manual steps](./Phase4_Manual_Steps-Days49-52.md).
