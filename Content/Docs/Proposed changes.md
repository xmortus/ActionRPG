# Infinite World character systems: project integration plan

**Status:** Reviewed plan; fixed class/profession growth, class-tier free attribute points, special trial rewards, source-tracked primary bonuses, resource regeneration, and the default shared damage path are implemented. Persistence is deferred.  
**Project:** ActionRPG, Unreal Engine 5.8.  
**Review basis:** C++ source, project configuration, and Unreal MCP editor, asset, Output Log, automation, and PIE checks on 2026-10-25–26. `/Game/NewMap`, the primary and secondary attribute assets, and the Warrior/Mage class assets were inspected. Phase-specific gameplay checks continue as systems are added.

## Goal and source discipline

Build a character system that evokes J.T. Wright's *The Infinite World*: six primary attributes, distinct class and profession paths, skills, training, trials, and meaningful tradeoffs. Preserve working inventory, equipment, skills, UI, and trial flows while evolving their shared stat and combat contracts.

The books are the inspiration for this game design. The [fan-maintained compendium](https://the-infinite-world.fandom.com/wiki/Compendium_of_Classes%2C_Professions%2C_Skills%2C_and_Abilities) is a research aid, not a rules specification. The [author has said](https://www.goodreads.com/author/20112398.J_T_Wright/questions) that public class information is incomplete. Record a book and chapter or passage reference before labeling a mechanic canon. Otherwise mark it **book-inspired** or **game design**.

| Mechanic | Treatment |
| --- | --- |
| Strength, Agility, Constitution, Dexterity, Intelligence, Wisdom | Book-inspired core, already represented by `EPrimaryAttribute`; retain these names. |
| Classes, professions, skills, and training | Central progression pillars. Fixed attribute gains from class and profession sub-levels are part of the game's book-inspired rule set; exact amounts are game design. |
| Free attribute and skill points | Separate balances. Trial rewards can grant either. Class level-ups grant fixed attributes plus 4 free attribute points for Basic and Specialized classes or 5 for Advanced classes. Professions grant fixed attributes only. The class-tier point rates are supported by book 1, chapter 15; fixed attribute gains remain class-specific game content. |
| Strength/Agility imbalance | Candidate from the fan compendium; verify in the books. Prototype as an optional configurable penalty, disabled by default. |
| Minor/Major Regeneration and possible costs | Candidate skill content; verify effects and tradeoffs before creating assets. |
| Health/stamina/mana formulas, armor, crit, dodge, true damage, respawn | Game design choices, not claimed book formulas. |

## Target rules and ownership

### Primary attributes and growth

`UAttributeComponent` remains the only source for final primary values. Distinguish base values, permanent earned growth, class grants, equipment grants, and timed effects. Each non-base grant needs a stable source key or handle, magnitude, and stacking policy. Reapplying a source replaces its prior grant; removing one source removes only its contribution. Apply sources in a documented deterministic order, clamp once, and broadcast only changed final values.

Training is a separate growth producer. Track practice by attribute and activity, apply configurable thresholds/cooldowns and anti-farming rules, then grant permanent growth once. Trials may award XP, skills, items, free attribute points, or free skill points through explicit reward definitions. Free attribute and skill points have independent balances. Class levels grant fixed, data-defined attributes and tier-based free attribute points; profession levels grant fixed attributes without free points. Preserve previously allocated points.

Class/profession unlock checks should use persistent attributes by default, so unequipping an item cannot invalidate an acquired path. Expose persistent and effective readings to the UI. Permit temporary/equipment bonuses for a requirement only when its data explicitly says so.

### Derived stats and current resources

`USecondaryAttributeComponent` keeps formula results (`MaxHealth`, `MaxStamina`, `MaxMana`, `Armor`, `CritChance`, `MoveSpeed`) and current health/stamina/mana for the first integration phase. Current values for non-resource entries have no gameplay meaning. `CanSpendResource`, `TrySpendResource`, `CanSpendResources`, `TrySpendResources`, and `RestoreResource` now validate the gameplay paths. Direct setters remain for damage, revive, and compatibility. Add a typed health-change and percentage API when a caller needs them.

When a maximum changes, preserve the current absolute value and clamp to the new maximum by default. Initial spawn fills each pool once. Death/respawn and explicit full-rest actions set values by their own rules. A stat/class/item change must not refill a pool. Percentage-preserving behavior, if desired, must be an explicit data setting.

Extend `USecondaryAttributeDataAsset` only for derived values used by actual gameplay. Formula coefficients, limits, and independent regeneration rates and delays live in data. The old proposal's numbers such as `100 + Constitution * 10` are test placeholders; they are not book rules and should not silently replace existing assets. Recalculate on source changes, not every frame. Resource regeneration now uses timers; death suppresses passive health recovery and removes temporary effects configured to end on death.

### Damage, healing, conditions, and life state

Keep Unreal `TakeDamage` as the external entry point for existing weapons and projectiles. Convert each hit into a typed request (amount, damage tag, causer, instigator, optional skill tag). One resolver validates life state, calculates mitigation, and applies health once. Return applied damage and outcome. The default request must reproduce today's untyped damage. Add physical/magical subtypes, critical hits, resistances, evasion, and true damage only when content needs them.

Move enemy and player health toward the shared resource/life-state path without losing enemy death behavior. A lethal enemy hit fires death once, disables movement/collision as configured, resolves the killer, reports a trial kill once, and broadcasts `OnEnemyDied`. Define player incapacitation, death, healing, and respawn separately in data.

Healing and damage-over-time use the same resource/damage APIs. A status definition owns duration, interval, stacking/refresh behavior, tags, and reversible modifier handles. Timers drive periodic effects. Expiration removes only that effect's contributions. Ordinary healing cannot revive a dead actor unless a dedicated revive rule allows it. Regeneration skills become effect definitions, with any attribute cost added only after book review and a design decision.

### UI, persistence, and data

Extend `UVitalBarsWidget` and `UCharacterStatusPanelWidget` with event-driven updates and source breakdowns. Show class and profession levels separately. Do not present `GetPlayerLevel()` as an independent progression track without explaining that it is currently a computed sum. Preserve the equipment stats display. Status indicators subscribe to effect events; avoid UMG per-frame numeric bindings.

Save stable IDs for classes, professions, skills, training milestones, equipment, trial history, and permanent growth; save current resources and only persistent effects. Rebuild derived values from data and grants on load, then clamp restored resources. Version the schema, handle unknown IDs, and document migrations before changing serialized asset fields. Runtime effect handles are not save IDs.

Persistence work in this paragraph is deferred. Current implementation work does not add a save schema. When persistence is added, save each class's highest level already awarded free attribute points so a load or class reselection cannot duplicate those awards.

For new C++ members follow project rules: `UPROPERTY()` on UObject member pointers, `TObjectPtr<T>` for UPROPERTY pointer fields, forward declarations in headers where possible, and Tick disabled unless required. Expose configuration/events to Blueprints while calculations stay in C++.

## Implemented progression slice

- Class and profession assets define fixed primary attribute gains per earned level. Warrior gains Strength and Constitution; Mage gains Intelligence and Wisdom; Blacksmith gains Strength and Dexterity. The current amounts are one point each per level and are provisional game balance.
- Earned class and profession gains remain applied when a path is deselected. Basic and Specialized class levels award 4 free attribute points each; Advanced class levels award 5. The first level of a newly acquired class counts, and returning to an earned class cannot award the same level twice. Profession levels award no free attribute points. Existing allocations remain intact; the legacy `AttributePointsPerLevel` asset field is ignored.
- Primary attribute bonuses now have stable source IDs. Class selection bonuses, earned class/profession growth, equipment slots, and timed effects can each be replaced or removed without disturbing other sources. Effective and persistent attribute readings are separate; class/profession unlock checks use the persistent reading. Source values are summed in stable order and clamped once. Unreal MCP confirmed a temporary Strength bonus on the live PIE player changed effective Strength from 1 to 6 while persistent Strength stayed 1, then returned effective Strength to 1 when removed.
- `USkillManagerComponent` owns a separate free skill point balance. Trial reward data can grant attribute and skill points independently; reward preview and character status show the skill balance. The Skills panel has Known and Learn tabs. Free skill points purchase a new skill from the player catalog only when its player-level, persistent-attribute, selected-class, and prerequisite-skill requirements are met. Existing item, class, and trial skill grants remain free. A skill starts at level 1 and gains levels through use XP alone; no point upgrade ranks, cost reductions, or cooldown reductions exist. The current catalog offers Minor Regeneration, Dash, Major Regeneration, and Ranged Attack with provisional costs and gates. Persistence is still future work.
- Known-skill tiles show the current level and XP toward the next level. The panel refreshes those readings from the skill experience event when a skill is used, so progress is visible without reopening it. The catalog purchase test now activates the newly learned skill and checks its XP and level-up path.
- Health, stamina, and mana now recover through separate timers after their values decrease. Current values remain clamped and do not refill on stat recalculation. The shared attribute asset sets health to 2 per second after 5 seconds, stamina to 20 per second after 1 second, and mana to 2 per second after 2 seconds. These are tunable game balance values. Health at zero does not recover passively.
- Unreal MCP verified the three edited progression assets after saving. A full `ActionRPGEditor` build and five focused MCP automation tests passed on 2026-10-25.
- A clean editor build and three focused MCP automation tests passed for resource regeneration and affected UI. MCP confirmed the PIE player uses `/Game/Data/Attributes/DA_SecondaryAttributes_Base` and that its saved regeneration values survived an editor restart.
- Enemies and players now use the same default damage resolver behind `TakeDamage`. The player has a one-time death transition, a Blueprint death event, and an explicit `Revive` entry point. Death stops movement and suppresses passive health recovery. Enemy `OnEnemyDied` and trial kill credit remain intact. Enemy and player melee hits carry a physical damage type. Skill projectiles preserve their skill data's Physical, Fire, Cold, Lightning, Poison, Magic, Dark, or Holy type for direct and area hits. Armor reduces physical hits using `ArmorMitigationScale / (ArmorMitigationScale + Armor)` on both players and enemies. Enemy Armor defaults to zero. The secondary attribute data asset and equipped item data can contribute player resistance percentage points for each typed hit; the combined reading is clamped to 0–100 percent and updates on equip or unequip. Enemies have editable per-type resistance percentages using the same 0–100 percent clamp and resistance-before-Armor order. Empty defaults add no resistance. Untyped hits retain their previous behavior.
- A clean `ActionRPGEditor` build succeeded for the damage changes. Four focused MCP automation tests passed, including player damage/revive, resource regeneration, combat death credit, and a real melee skill hit against an enemy. The editor's MCP server reconnected after reopening.
- Validated resource spending now rejects invalid or insufficient costs atomically. Skills reserve mana/stamina before activation and refund failed casts. Potions check `CanUse` before restoring and consume only after successful restoration. Ordinary healing cannot revive a dead player.
- Equipment now enforces `EquipmentRequiredLevel` against the project's computed player level before occupying a slot. Rejected equips leave the slot unchanged; item data still defaults this requirement to level 1. Both inventory context menus disable **Equip** when a requirement is unmet, show a reason on hover, and include the required level in the button label.
- Timed status effects have configurable duration, interval, stacking policy, maximum stacks, per-tick resource values, and death removal. Minor Regeneration restores 3 health per second for 8 seconds at 8 mana; Major Regeneration restores 8 health per second for 10 seconds at 30 mana. These are provisional game balance values. Their effect definitions, skill data, and skill Blueprints were created and saved through Unreal MCP. Minor Regeneration is learned from the skill catalog with a free skill point, then can be assigned to a skill slot. Major Regeneration requires Minor Regeneration. Minor Regeneration's cost fits the starting 10-mana pool.
- The player death screen offers explicit respawn at PlayerStart after a configurable 3-second delay, with the original spawn transform as fallback. Unreal MCP PIE validation applied lethal damage to the live player, observed the death screen and enabled respawn button, clicked it, and confirmed the screen closed and health returned to 100/100. The final editor build and all 22 ActionRPG MCP automation tests passed after the class-tier UI change. MCP confirmed existing Warrior and Mage assets use the Basic tier. Persistence remains deferred.
- Attribute training now tracks practice by attribute and activity. Successful player melee damage to an enemy records Strength practice. A configurable milestone grants permanent Strength through its own `Training.Strength` source without changing free attribute points. Activity and target cooldowns plus a per-window cap limit repeated farming. A PIE `RPGTrainingStatus` command shows progress and earned growth. Current defaults (20 accepted hits per +1 Strength, 0.5-second activity cooldown, 3-second target cooldown, and 10 accepted hits per 60 seconds) are provisional game balance. Other activities can be wired to the same component as their gameplay actions are implemented; training persistence remains deferred.
- The placed `TrainingEnemy` in `NewMap` now recovers health and hit collision four seconds after defeat. This lets melee practice continue after its one-time combat trial completes; trial rewards still apply only once. Other enemies retain their existing defeated state unless recovery is enabled on them.
- Dodge input now performs a stamina-costing dash with a brief avoidance window. Avoiding an enemy hit or moving away from a nearby enemy earns Agility practice under configurable cooldown and window limits. Training milestones and earned permanent growth appear in the character status panel. Values are provisional game balance.
- A configurable close-range enemy strike gives the training enemy an active combat role. Surviving meaningful enemy damage earns Constitution practice under the same milestone and anti-farming framework; the character status panel shows its progress.
- All six primary attributes now have gameplay practice paths. Dexterity comes from a damaging ranged projectile hit, Intelligence from a damaging magic projectile hit, and Wisdom from effective player-sourced healing effects. The NewMap player starts with Fireball on hotkey 7 for testing, and Fireball's provisional mana cost is 8. The six counters and earned gains appear in Character Status. The shared projectile Blueprint now inherits the native `ASkillProjectile` hit logic so magic and ranged hits reach their training paths.
- Fireball's existing area damage now records Intelligence practice and skill hit XP for nearby enemies that actually lose health. Projectile ownership is initialized on BeginPlay so the caster is ignored by direct and splash impacts. Character Status labels its computed class-plus-profession total as Combined Level and explains it on hover; the total is zero with no selected paths, while level 1 paths remain available as starting choices. The separate path levels remain visible on Overview.
- Magic and ranged skills now report failed projectile creation as a failed activation. The skill component refunds reserved mana or stamina and grants no cooldown or use XP when that happens. A focused regression also covers null skill activation. Unreal's Python export names the game's damage enum `RPGDamageKind` to avoid collision with the engine's `DamageType` class; its C++ and Blueprint values remain the same.
- Character Status now exposes a hover breakdown for each primary attribute. It separates base, allocated free points, stable modifier sources, and any attribute-cap adjustment, so class gains, training, equipment, and temporary effects can be audited against the displayed total.
- Character Status now has Overview, Training, Sources, and Effects tabs. The dedicated Training page gives six practice paths room to grow; the Sources page is scrollable and displays all six attribute breakdowns at once. The Effects page lists active effects, stacks, remaining duration, and periodic resource changes. A compact effect list appears above the vital bars and hides when empty. Effect change and whole-second events update both displays without per-frame UMG bindings. The summary balances remain visible across tabs.
- The Equipment stats panel lists nonzero effective damage resistances beside Armor and other combat stats. It updates from the same equipment-driven secondary attribute recalculation, so equipping and removing resistance gear changes the display.
- Melee hits use a damaging main-hand weapon's `WeaponDamageType` and add its `WeaponDamage` to the melee skill's base damage. Unarmed attacks use the skill data's type and base damage. The additive rule is provisional game balance; the weapon type shown in Equipment now matches the damage event used for Armor and resistance checks.
- Both carried-item grids now use one item-data tooltip. Equipment tooltips include required player level, required primary attributes, primary and secondary bonuses, weapon damage bonus and type, and damage resistance bonuses; empty slots clear their tooltip. The Equipment stats panel labels weapon damage as a bonus to match the additive melee rule.
- Paper-doll drops validate the target slot as well as the item's level and attribute requirements. Valid targets highlight green, invalid targets red with a failure reason, and dropping on the wrong slot no longer equips the item elsewhere.
- Equipping into an occupied slot is rejected with an explicit reason. The existing equipped item stays in place and the new item remains in inventory; unequip first to change gear.
- Unequipping to carried inventory checks capacity and weight before removing the gear. A failed transfer leaves the item equipped.
- Inventory capacity preflight counts free units in partial stacks and empty slots before accepting a multi-stack pickup. Oversized pickups are rejected before adding any items, so the world pickup cannot duplicate a partially added quantity.
- World drops reject zero or oversized quantities and leave the source stack unchanged. A pickup quantity mismatch also cancels the drop before inventory removal.
- Consumable quick-use bindings follow the same item instance when carried slots move or swap. When a bound stack fully merges, its binding follows the surviving stack unless that stack already has a quick-use binding; in that case the redundant source binding clears. Item-instance quantities stay aligned with slot quantities after merges.
- Dropping part of a consumable stack keeps its quick-use binding. Dropping the entire stack still clears it.

## Implementation sequence and acceptance gates

1. **Unreal MCP baseline.** Query live editor state, target `/Game` asset paths, Blueprint defaults, PIE/compilation status, and recent Output Log entries. Save relevant assets before changes. Confirm which data assets the player/enemy actually use. If the editor is unavailable, stop before any `.uasset` mutation.
2. **Primary modifier provenance.** Implemented in `UAttributeComponent` without renaming serialized types. MCP tests cover equip/unequip, class selection/removal, repeated grants, and timed-effect removal. Legacy allocated points remain intact.
3. **Resource API and max-change rules.** Validated spending/restoration and skill/potion migration are implemented. Add a typed health-change API when the damage system needs it.
4. **Shared damage/life-state path.** Default untyped damage, player death/revive, enemy trial credit, and Armor mitigation for tagged melee hits are implemented and covered by MCP automation. A PIE kill-credit check and additional damage types remain acceptance work.
5. **Regen and effects.** Resource timers, regeneration effect assets, stacking, expiration, death cleanup, and reversible primary attribute sources are implemented. Pause/resume coverage remains future work.
6. **Lore-facing progression.** Fixed class/profession gains, tier-based class free attribute points, and all six primary attribute training paths are implemented. Validate the six actions in PIE, then tune milestones and anti-farming limits. Keep free attribute and skill point balances separate; the 4/5 tier rates are supported by book 1, chapter 15, while practice thresholds are game balance.
7. **UI.** The vital bars, player death/respawn screen, primary attribute source breakdowns, and active effect indicators are implemented. Save/load and migration tests are deferred.

After each code phase, inspect the Unreal Output Log through MCP, compile with the editor's Live Coding workflow when connected, and validate affected assets/gameplay in PIE. Do not issue a blocking external build while the editor has an active Live Coding session.

## Decisions for book review and gameplay design

- Treat exact attribute relationships, especially Strength versus Agility and regeneration costs, as game design until there is a reliable book reference.
- Decide whether `GetPlayerLevel()` should include profession levels in player-facing displays; preserve current behavior until UI and requirement logic are audited.
- Free attribute points are allocatable from trials and ordinary class levels. Basic/Specialized class levels award 4 and Advanced levels award 5, alongside fixed gains. Profession levels grant fixed gains only. Free skill points have a separate balance. Existing allocations must survive.
- Player death stops movement and passive health recovery; the death screen offers delayed explicit respawn. Decide whether future effects may persist through death and what, if any, respawn consequences should apply.
- Choose combat subtypes and balance values only after a real content use case exists.
